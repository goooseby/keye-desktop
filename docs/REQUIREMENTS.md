# 产品需求与验收范围

## 目标

保留课页已经验证的用户流程：在学校网页中登录，按所选日期范围自动扫描课表，按课程和课次获取课件，在本地资料库逐页预览与排除无效页，最后快速导出或整理后导出 PDF。新版本的主要改进是减小分发体积、提升翻页和窗口交互的稳定性，并让程序、用户数据和开发工具彼此分离。

## 不能退化的行为

1. 课程是扫描结果的一级单位；一门课程下有多次课，每次课对应一份课件。文件也按课程、课次组织。
2. 登录在独立网页窗口完成，后台自动判断登录是否成功；日期范围变化自动扫描，按钮仍允许强制重新扫描。
3. 整理不是导出的前置条件。可直接快速导出，也可逐页筛选。原始页保留，排除状态可恢复。
4. 缩略图、放大预览、键盘上一页／下一页、`E` 排除或恢复、`Shift` 连选、批量操作与撤销继续可用。
5. 首次导出时才询问保存目录；取消选择不会产生导出任务。之后可在设置中改变。
6. 下载、预览、合成 PDF 在后台运行，界面不能因耗时工作卡住。失败任务应可诊断与重试。
7. 本地资料与程序安装文件分开。升级程序不能清除课程、原图、排除状态或导出设置。

## 第一阶段：架构验证

首个样机只需在 Windows 10/11 上显示独立窗口，并证明 WebView2 前端能够调用 Rust 命令。样机 UI 不使用真实或伪造课程数据；它明确标识尚未迁移的功能。

正式迁移前，先用一个有限的端到端试验验证四个高风险环节：校园网页完整登录、Rust 侧读取 HTTP-only Cookie、课程扫描与单份下载、含大量图片的快速翻页和 PDF 输出。样机与旧项目必须可同时存在。

## 非目标

- 当前阶段不改动旧版程序、不发布替代旧版的 Release，也不自动迁移用户资料。
- 暂不做 macOS/Linux 发行。核心设计尽量保留以后扩展的可能，但 Windows 体验优先。
- 不在新架构中加入与课件工作流无关的功能，也不为了框架而重画成熟界面。

## 成功标准

在同一台基准机器上记录旧版与新版的安装包大小、首次启动耗时、空闲内存、47 页及更长课件连续翻页时的响应、批量导出耗时。数值以实测为准，不承诺某个框架必然消除所有渲染问题。测试使用项目内生成或授权的样例；涉及学校账号与真实课程的验证由用户在应用中完成。
