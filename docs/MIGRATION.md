# 迁移路线与数据保护

## 开发顺序

1. **架构样机**：独立目录、命名、工具链、窗口、UI 到 Rust 命令的连通性。当前阶段。
2. **最小真实闭环**：学校网页登录 → 识别 Cookie → 扫描一门课程 → 下载一份课件 → 预览与排除 → 导出 PDF。优先解决登录与快速翻页风险。
3. **资料库与完整界面**：搬迁课程／课次组织、批量操作、设置、备注、任务恢复；迁移现有页面视觉语言，但逐项检查交互。
4. **用户数据迁移**：在新程序中增加“从旧版导入”，由用户主动选择旧资料库目录，先预检查、备份，再复制到新目录并校验；原目录保持不变。
5. **发行验证**：在干净的 Windows 环境检查 WebView2 安装、首次启动、权限、程序更新及旧版并存，然后再考虑公开发布。

## 当前边界

任何开发脚本、测试和样机都只使用 `keye-desktop` 项目里的文件。不会扫描或触碰旧版安装目录、ProgramData 或用户真实资料。即使以后实现导入，也必须由用户明确选择来源和目标，提供可预览的迁移摘要；失败时删除未完成的新副本，不能改写源目录。

旧版代码及界面是行为参考，不作为新版本的自动更新来源。新版需要自己的应用标识、数据目录、GitHub 仓库和签名密钥，避免覆盖旧版。

## 决策记录

- 正式应用名继续用“课页”；技术仓库名统一为 `keye-desktop`，不把版本号或技术栈写进名字。
- 首期只面向 Windows，选择 Tauri 2 + Rust + TypeScript。现有 UI 可逐步移植；框架好坏以真实登录、翻页和打包验证决定。
- 不将 NativeAOT、Slint 或 Qt 作为并行主线；若登录或渲染样机未通过，再有证据地重新评估。
